# Paragraph patterns

Adapted from level 7 of Writer Science's *Anatomy of a Great Essay*, PDF p. 4. Examples below are invented to demonstrate structure; they are not evidence or quotations from the source.

Choose according to the relationship between ideas. Patterns can combine within a paragraph; use them to repair information flow, not to impose a repetitive sentence formula.

## Constant theme: elaborate one subject

Keep the same Topic across clauses while each Comment adds a different aspect. Use for explaining a single entity or proposition.

**Shape:** A → detail 1; A → detail 2; A → detail 3.

> The library stays open until ten. It lends tools as well as books. It also provides a quiet place to study.

The recurring Topic anchors the paragraph. Clear pronouns can carry that continuity without repeating the noun each time.

## Linking pattern: carry new information forward

Make information introduced in one Comment the Topic of the next clause. Use for a mechanism, causal sequence, or stepwise explanation.

**Shape:** A → B; B → C; C → D.

> Each request enters a queue. The queue feeds a worker. That worker records the result in a shared log.

Each sentence gives the next one a recognisable starting point. Repair a break by reordering information or naming the relationship; a transition word alone cannot supply a missing logical link.

## Super theme: unfold a category

Introduce a broad category in the Index, then make its members or aspects the Topics of subsequent clauses. Use when the reader can recognise how those details belong together without an explicit list in advance.

**Shape:** category → member A; member B; member C.

> The workshop offers several quiet spaces. Window seats suit solitary reading. Side rooms allow private conversations. A sheltered courtyard gives visitors somewhere to pause.

The spaces share a parent concept. If a detail's membership is unclear, explain the connection or move it elsewhere.

## Theme preview: announce the parts

Name the forthcoming Key Terms in the Index, then develop those terms as Topics. Use when a comparison, unfamiliar framework, or set of distinctions benefits from an explicit roadmap.

**Shape:** preview A, B, C → develop A → develop B → develop C.

> The review has three stages: scope, evidence, and decision. Scope defines the question. Evidence establishes what happened. The decision states what should change.

Keep the announced terms recognisable and follow the preview's order unless the argument gives a clear reason to change it. Unlike a super theme, this pattern explicitly names the parts before developing them.
